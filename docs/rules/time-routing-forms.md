# Timezones, routing and forms

The full rules behind the one-line summaries in `CLAUDE.md`. Moved here word for word from `CLAUDE.md` on 19 Nov 2026 (CLAUDEMD.1); keep the two in step when a rule changes.

**Timezones, routing, forms**
- **A studio's clock is its `locations.timezone`.** Wall-clock columns (`bookings.booking_date`/`start_time`, `shift_blocks`, `race_events`, quiet hours, schedules, Sonos windows) are local time in their row's location zone (Europe/Dublin for every UN1T studio): never `new Date(\`${d}T${t}Z\`)` (adds the summer-time offset); convert with `zonedWallClockToInstant(date, time, zone)`. An instant (`*_at`) is never re-zoned; only its rendering and its day bucket take a zone. **The ONLY way to do zone maths is `@/lib/location-time` (web/server: `getLocationZone`/`getLocationZones` throw `LocationZoneReadError` on a DB error, so a cron skips; `zoneOfLocation(row)` when you hold the row) or `shared/zoned-time` (phone, shared, champ-app).** "Today" is `todayStrIn(zone)`; compare zones through `canonicalZone()`. Platform-level decisions (billing month D5, platform heartbeats, ops throttles) use `PLATFORM_TZ`. Never mix local-time `Date` parsing with `toISOString()` formatting; test date code in Europe/Dublin *and* America/New_York across a DST change. `check:guardrails` (`scripts/check-dublin-zone.mjs`) bans the `'Europe/Dublin'` literal and every `dublin-time` import outright (TZ.18b: the baseline is gone): the allowlist is `shared/zoned-time.js` (defines `PLATFORM_TZ`), the two legacy `dublin-time` modules and their own tests (kept only because champ-app mirrors `shared/dublin-time`), and `shared/zoned-time.parity.test.js`. Tests may name the zone, never import `dublin-time`. `no-utc-today`/`no-zulu-template-date` still apply.
- **Public pages must live OUTSIDE auth-gated `src/app/<segment>/`** (layout auth gates run first) AND be added to **FOUR** allowlists — miss one and the page half-works in a way nobody notices: (1) `src/proxy.js` `publicPaths` (else an anonymous request 307s to `/login`), (2) `AppShell`'s `PUBLIC_PATHS` (else the server renders the page and the client shell then blanks it and redirects — the page "flashes then vanishes"), (3) the `un1t-marketing` `allowedPaths` in `src/lib/brands.js` (else `un1tdublin.com` fallback-rewrites it to `/welcome`), and (4) `DB_BRAND_DEFAULTS.allowedPaths` in `src/lib/tenant-domains-edge.js` (the SAAS-8 tenant-domain tier — same rewrite, for any `tenant_domains` host). This invariant said "BOTH" and named only the first two until PUBPATH.1, which is part of why the class keeps recurring (`/unsubscribe`, `/privacy`, `/preferences`, `/account-deletion`, `/embed`). **Allowlist the whole FLOW, not just the entry page**: a signup page whose paid leg posts on to a checkout needs the checkout listed too (`/event/` without `/event-pay/` takes the registration and then rewrites the payer to `/welcome`). Matcher shapes differ — proxy + brands are raw `startsWith` (so directory entries carry a trailing slash), `AppShell` is segment-aware (`=== p || startsWith(p + '/')`, no trailing slash). Regression guard: `src/public-compliance-paths.test.jsx`. Since PAGES.1 a `landing_pages` row (kind campaign, publish_state live/coming_soon/retired) is public through the edge slug tier (`src/lib/public-pages-edge.js`) and the `x-public-page` request header, with no allowlist edit; reserved app segments can never become page slugs.
- **`?edit=1` on `/welcome` and `/welcome/<path>` is a STAFF preview, not a public mode** (EDITGATE.1). The page honours it only when `getCurrentUser()` resolves a staff session with access to the page's studio (the editor iframe is same-origin with `/settings/landing-page`, so the cookies travel), and even then seeds `EditModeOverlay` with `clientSafeBlocks()` (`src/lib/landing-page-blocks.js`, `CLIENT_WITHHELD_KEYS`): a block's Glofox / un1t.online product ids and lead attribution never leave the server as part of a block object. The editor pushes the full blocks itself over postMessage. A new block field that is operator configuration rather than page copy goes in `CLIENT_WITHHELD_KEYS`; a new place that hands a whole block to a client component goes through `clientSafeBlocks()`. Before it, any visitor appending `?edit=1` got the whole blocks array in the RSC payload, and `/welcome?edit=1` seeded from the estate's most recently edited page, any tenant's.
- **Every `<button>` in a `<form>` defaults to `type="submit"`** — set `type="button"` on every non-submit (tab pills, close X, secondary actions). **Lint-enforced since BTNTYPE.2** via `check:guardrails` (`no-untyped-button-in-form`), which flags an untyped `<button>` only when a `<form>` is genuinely its JSX ancestor. It deliberately stays silent on a `{...spread}` (the type may arrive through it), a dynamic `type={expr}`, and uppercase `<Button>` — precision beats coverage in a rule that runs at ERROR across the repo. **Blind spot:** an AST rule sees one JSX tree, so a button reached across a component boundary (`<form>` renders `<Foo/>`, `<Foo/>` renders the button) is invisible — the rule is a floor, not proof. Baseline was clean when it landed: all 143 in-form buttons already carried a type, and the ~267 untyped ones live outside any form, where the default is inert.

| #2335 | WA-BSUID.2 / WA-LIMIT.1 — phone-less WhatsApp senders, and the messaging limit read | 2026-11-09. From the 9 Nov audit of Meta's WhatsApp platform changes. **WA-BSUID.2:** a WhatsApp user with a username can hide their number; Meta then omits `messages[].from` and `contacts[].wa_id` and names the sender by a business-scoped user id (`from_user_id`). The webhook called `message.from.startsWith`, so such a message threw, was lost (dedupe key already claimed, 200 already owed) and, because the whole POST loop sat in one try/catch, took every later message and delivery status in that delivery with it. New `src/lib/whatsapp-address.js` (`inboundSender`, `isBsuid`, `recipientFields`, `conversationAddress`). The webhook now handles each message and each status in its own try/catch; the phone is optional (contact matched by `wa_bsuid`, thread by the existing partial unique `(location_id, wa_bsuid)`, a new thread inserted with `wa_phone` NULL + `wa_bsuid`, the number stored on it once Meta sends it). All eight Cloud API send payloads go through `recipientFields` (`recipient` for a BSUID, `to` for a phone, unchanged). Mia, the greeting, the studio picker, the STOP acknowledgement, staff send, react, send-flow, card sets, the agent thread notice and the voice text fallback address the thread's phone, else its BSUID. A BSUID is never treated as a phone (allow-list, Mia's phone match, the same-number STOP sweep). **WA-LIMIT.1:** Meta deprecated the phone-number field `messaging_limit_tier` and stopped returning it; the health poll wrote the NULL over the stored tier, which switches the blast/drip budget gate off. `fetchNumberHealth` now reads `whatsapp_business_manager_messaging_limit` in its own request (Graph v25.0; the old field stays as a fallback), `normalizeMessagingLimit` stores one spelling for tier strings, bare numbers and `-1`, `TIER_2K` is ranked, labelled and gated, the poll keeps the last known tier when Meta gives none and reports `limit_unknown`, and the capability webhook notice reads `max_daily_conversations_per_business`. No migration. **Not verified:** no phone-less message has been seen here (tested against Meta's documented shape), and the new limit field has not been read live: check `whatsapp_numbers.messaging_limit_tier` after the first poll post-deploy. **Not covered:** outbound paths keyed on `contacts.wa_phone` (broadcasts, sequences, follow-ups), system messages (`user_changed_user_id`), the Graph v21.0 pins (removed 21 Jan 2027) and the marketing move to `/marketing_messages` (13 Oct 2027). |

| #2541 | INBODYDEDUPE.1 — the same InBody scan is never recorded twice | Scans were keyed on the phone as each road spelled it plus the time, so a scan that came in through both the webhook (0871234567) and a "Sync InBody" backfill (+353871234567) made two rows, and the key carried no studio. Mig 871 adds `matched_phone9` (the last nine digits, generated) and a unique index on (studio, phone9, scan time). It stops and reports the count if duplicates already exist, and deletes nothing. Apply it before the deploy. Every writer upserts on that key, so a repeat delivery updates the one row. A bridge event whose scan already exists is marked processed and counted in `duplicates`; it is never left pending. |

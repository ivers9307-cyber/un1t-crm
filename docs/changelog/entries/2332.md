| #2332 | HOSTPORTAL.1 — the host portal's six places | 2026-11-09. PR 1 of 3 of the host portal reorganisation (spec `docs/superpowers/specs/2026-11-09-host-portal-reorganisation-design.md`, plan `docs/superpowers/plans/2026-11-09-host-portal-reorganisation.md`). The signed-in portal's nav goes from Dashboard · Contacts · Emails to **Overview · Events · Contacts · Emails · Earnings · Your page**, on its own row under the brand (the strip scrolls sideways on a phone and keeps the active link in view). `/host` is now a short Overview: what needs attention (Stripe not connected; a needs-changes event with the reviewer's note), the next event that is actually on sale (`eventIsPublic`) with booked / waitlist / page views / money so far, and the next three events. New `/host/events` (Needs action, Upcoming, Series, Past; a row opens the event, a draft keeps Submit for review, past rows show the public rating average), `/host/earnings` (balance, all-time tiles, by event, payouts, statements; a non-Stripe host still sees gross and refunded only) and `/host/page` (the public page editor in visitor order with both share links and QR codes; a save now says "Saved." and shows the server's canonical values). New libs: `src/lib/host-portal.js` (host-scoped event loader, grouping, landing link, net/gross label, row detail, rating averages) and `src/lib/host-session-fill.js` (per-session booked count on the booking gate's own rule: confirmed plus unpaid entries still holding a place; `loadWaveRegistrations` / `groupByWave` are now exported from `registration-move.js`). `HostPayouts` became one fetch behind `HostPayoutsProvider` with `HostBalance` and `HostPayoutList`; `HostListPageEditor` gained a `sections` layout beside the unchanged drawer; `HostSignupPageCard` is gone. Three bridges until PR 2 rebuilds the event page as tabs: a "View event page" link and an Edit link (non-published events) in the event header, and Submit for review on the edit page for a draft or needs-changes event, so nothing a host can do today is lost between PRs. A failed read says "unavailable" on every new block, never a 0. No API behaviour change, no migration. `src/lib/customer-link-paths.test.js` and `tests/un1t-literal-sweep.test.js` follow the moved pages. Not checked in a browser (no host session locally): the preview needs a walk as a host by event status and at 375px. |

| #2364 | SHELLYEVENTS.1 — events held at a studio keep its Shelly timers on | 2026-11-14. Class-mode Shelly groups followed only the class timetable, so a studio hosting an event with no class on switched off mid-event. **Mig 832 (applied):** `race_events.venue_location_id`, the studio an event is held at (NULL on a host event = elsewhere; NULL on a studio's own event = its own location); upcoming host events held at our studios linked by hand. `src/lib/shelly/studio-events.js` loads the day's published, active events held at the studio as class-shaped occurrences (first start time to `duration_minutes`, default 120, after the last start); `loadDayOccurrences` merges them, so the cron, toggles, group list and day preview all follow, and a failed event read fails the load (state held, never "no event"). The day preview gains an Events lane (`events` on `GET /api/shelly/preview`). Host event form: "Where is it held?" picker of the organisation's studios (active, not a host anchor, address on file; `src/lib/event-venue-studio.js` judges the id on create and update; a body without the key leaves the link alone); the review queue shows the studio; duplicates carry it. A studio change on a published host event does not go back to review. Not walked in a browser. |

| #2558 | XERO429.1 — wait out Xero's rate limit instead of failing the batch | 2026-11-23. `xfetch` (`withFreshToken`, `src/lib/xero/client.js`) now handles a 429: it reads `Retry-After` and `X-Rate-Limit-Problem` and, when the wait fits the caller's `rateLimitWaitMs` (default 4 s), waits and repeats the request, up to 3 attempts; the daily limit is never waited for, and a refusal carries code `rate_limited` / `rate_limited_day` with a plain message. `pushQueueRowToXero` passes the budget through. Bulk send gives each push 65 s, stops the batch leaving later rows untouched when Xero still refuses (`xero_busy`, `xero_daily_limit`), and stops starting rows after 225 s (`out_of_time`). No migration. |

| #2200 | SONOSGONE.1 — a deleted Sonos household offers Reconnect instead of "Sonos isn't answering" | 2026-10-25. Sonos answers HTTP 410 Gone to a household's groups read once that household was deleted or re-created (a system reset/re-setup); the OAuth grant still refreshes. Live at Hatch Street: the Studio music page showed the "isn't answering (HTTP 410)" notice with NO Connect button (the not-connected panel renders only without a connection row), so nobody could re-link from the UI although re-linking is the fix (the callback upserts on `location_id`). Now `isHouseholdGone` (410/404, `src/lib/sonos/client.js`) makes `GET /api/sonos/household` answer `{ connected:false, reason:'household_gone' }`, the panel explains it and the button reads **Reconnect Sonos** (for `refresh_failed` too; link still `/api/sonos/connect`); `sonos-reconcile` counts it as `householdGone` and logs "household gone — re-link needed", never `sonosDown`, no DB writes; the devices widget treats it as a configuration state. No migration; callback, connect, refresh and playback untouched. |

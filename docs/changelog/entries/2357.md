| #2357 | PMUNSUB.1 — an existing broadcast stream is switched to Custom unsubscribe handling | 2026-11-12. Marketing email from UN1T Group's own Postmark server carried two Unsubscribe links: the CRM's footer and one Postmark appended, because that server's `broadcast` stream was on Postmark-handled unsubscribes (found in the first live MCPEMAIL.1 send; the setting was confirmed in the Postmark dashboard). `ensureTenantServerStreams` (`src/lib/postmark-account.js`) only set Custom handling when it CREATED the stream and returned as soon as one existed. It now PATCHes an existing `broadcast` stream to Custom when its handling is anything else or is not reported, and returns `{ created, handlingFixed }`. `ensureServerWebhooksRecorded` (`src/lib/email-domain-service.js`) runs that stream check on a server whose webhooks are already stamped too, on provision and on Verify / Re-check DNS, since both live tenant servers are stamped; webhooks are still registered once, and a failed stream check on a stamped server is logged and never shown as a webhook failure. Postmark may refuse Custom for an account not approved for it. The live switch happens on the next Verify / Re-check DNS press for the organisation, or by hand in the Postmark dashboard. No migration. |

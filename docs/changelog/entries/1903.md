| #1903 | CARDOCUPLOAD.1 — car documents upload through a signed URL (files over 4.5 MB work) | 2026-10-01. Follow-ups C124 (found reviewing C102). **Web only; no migration, no OTA, no mobile change** (the phone only reads car documents). DocumentsCard posted multipart to `POST /api/cars/[id]/documents` and called a bare `res.json()`: Vercel's plain-text 413 over ~4.5 MB threw, the spinner stuck, no error showed, so the bucket's 25 MiB (mig 687) was unreachable. Now `POST …/documents/sign` (the multipart route's gate, moved to `src/lib/car-documents-gate.js`; doc type, size ≤ 25 MiB and type checked on the declared file, an unlabelled one judged by its first bytes sent as `head`) mints `<car>/<doc_type>/<uuid>.<ext>` with `createSignedUploadUrl` and returns the canonical `content_type`; the browser `uploadToSignedUrl`s the file re-typed as that (the bucket's allowed_mime_types applies to signed uploads, so an unlabelled file or alias sent as itself would be refused); `POST …/documents/finalise` checks the slot is this car's, refuses a replay (409), reads size + Content-Type back from Storage, re-judges the type (unlabelled → stored bytes sniffed, HEIC included) and requires it to match, removing the object on any break, then records via `src/lib/car-document-record.js` (shared with the multipart route: same row, orphan rollback, bookkeeper-queue enqueue, same 201 shape). Client: `src/lib/car-document-upload-client.js` (`readUploadJson` parses every response safely, never throws); the picker clears its spinner in `finally`. Multipart route kept, same answers (a failed car read is now 500, not 404). openapi.js, role sweep, bucket guard (check 5). |

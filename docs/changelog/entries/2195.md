| #2195 | OPENAPI-EVENTS.1 — the event list, create, read, update and retire routes are in the OpenAPI spec | 2026-10-24. `POST /api/events` and `PUT /api/events/[id]` were never registered in `src/lib/openapi.js` (noted by #2194), nor were `GET /api/events`, `GET /api/events/[id]` and `DELETE /api/events/[id]`. All five are registered now (tag Races, cookie or Bearer session), each description naming the gate the handler enforces (`races` resolved at the event's or body's studio, 404 not 403 for an event the caller cannot see, ADMIN_ROLES for a `host_id` change, `judgeEventOwnerChange` for a `location_id` move, MANAGER_ROLES for the retire, the HOST-EDIT.1 org-admin exception) and the codes it answers (201 create, 400 validation / `invalid_host` / `invalid_template` / `invalid_sending_location`, 409 slug clash and `duplicate_wave_time`). The bodies are the handlers' own Zod objects: the two inline schemas moved to `src/lib/event-save-schemas.js` (`EventCreateFields`/`EventCreateSchema`, `EventUpdateFields`/`EventUpdateSchema`, the two wave shapes), which the route files import and re-export as `CreateSchema`/`UpdateSchema`, so `waves`, `charity` (CHARITY.9/12), `find_team` (FINDTEAM.6) and `entry_policy` (ENTRYPOLICY.1, its keys and defaults rendered from `ENTRY_POLICY_DEFAULTS`) are documented from the object the handler validates with, and a field added there reaches the spec with no change to openapi.js. No route behaviour changed; no migration. `src/lib/openapi.test.js` and `src/lib/event-save-schemas.test.js` pin it. |

PR 1 of the host features design (`docs/superpowers/specs/2026-11-08-host-event-features-design.md`). A host event can carry 1–12 session times (`HostEventSchema.sessions[]`; `src/lib/event-sessions.js`: `judgeSessions` refuses a swap of kept times or the removal of a session with live entries before any write, the host PUT judges first so a refused change never pulls a published event back into review, and only an existing session's time change re-reviews). **Duplicate** (`src/lib/event-duplicate.js`; `POST /api/host/events/[id]/duplicate`, `POST /api/events/[id]/duplicate`; `DuplicateEventButton` on the host event page and the staff events list): a draft copy on a new date with every operator field, every session, the registration window shifted by the date delta and its own copy of the hero file. **Series** (mig 817: `event_series` service-role only + `race_events.series_id`; `src/lib/event-series.js`): "Make this a series" on the host event page copies the event onto a list of dates (weekly/fortnightly/monthly helpers), the dashboard lists series with their page copy editor, the host form gains a Series select (a body `series_id` must be the host's own), `/event/series/<slug>` lists every published upcoming date, `/h/<slug>` groups cards under their series. A hosted event's sessions are never windowed (`timePickerWaves(kind, waves, { hosted })`). `tests/branding-bucket-guard.test.js` gains `LIB_WRITERS` (a lib may only `.copy` inside `race-hero/`).

| #2067 | TVSCENE.1 — three rotating idle scenes on the studio TV board | 2026-10-16. The public TV board (`/tv/live/[token]`) showed "Waiting for class to start" over a black screen whenever no heart-rate band was connected, roughly 80% of the day and often class time too. It now rotates three scenes in that state: Up next (non-cancelled `class_occurrences` in the next 24 hours, time and name only, in studio-zone time), Earned this week (individual `contact_achievements` as first name plus last initial, with the opt-out and studio scoping applied), and the operator's pushed card (`tv_content` for that display). Each scene holds 30s and the scene index is DERIVED FROM ELAPSED TIME (`sceneAt` in `src/lib/tv-scenes.js`), not a timer: the board already re-renders every second, and a dwell timer in the stage is exactly the #2066 failure shape (an effect that depends on a callback identity changing every second, so the timeout never fires). A scene with nothing to show is skipped, never drawn empty; if none has content the stage falls back to the old empty board. The three reads live in `buildIdleContent` (`src/lib/tv-idle-content.js`), called only from the existing no-sessions branch of `buildLiveBoardPayload`, so a live class pays nothing. Each read fails to absent (a studio TV must never show a 500) with a structured `logWarn` throttled to one line per read per location per 5 minutes, carrying a `suppressed` count, so a permanent fault is loud without burying the log. `up_next` and `earned` go through a 60s per-location in-process cache, because live-poll.js only backs off overnight (an idle board polls every ~4s) and `earned` has no `earned_at` index and no `location_id` predicate; failed reads are never cached, and the operator read is uncached so a push appears within one poll. Storage refs are resolved to public bucket URLs server-side (a raw bucket path in an `<img>` is a broken image held for the whole dwell). Backfilled achievements (`metadata.backfilled`) are excluded in the query and again per row, so a backfill cannot read as "earned this week". A dead operator image drops the scene (the label still draws if there is one) for a 10-minute expiry, then is retried, so one blip at 3am cannot silence it until Chromium restarts. Two standing rules: NO aggregate studio metrics ever (no counts of members, sessions or achievements, and no capacity or booked count on a class), and unlinked bands stay visible.

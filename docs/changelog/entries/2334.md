| #2334 | HOSTPORTAL.3 — the last 30 days on the host Overview | 2026-11-09. PR 3 of 3 of the host portal reorganisation (spec `docs/superpowers/specs/2026-11-09-host-portal-reorganisation-design.md` § 6.3, § 7), stacked on #2333. The portal Overview (`/host`) gains a "Last 30 days" row between "Next up" and "Coming up": Bookings (confirmed registrations in the window across the host's events), Net earned (Stripe) or Gross collected (any other host), Event page views, and List signups with the total contact count beneath. New `src/lib/host-rollup.js` (`loadHostRollup`): four `head: true` exact counts on `race_registrations`, `event_page_views` and `host_contacts`, each scoped to the host's own event ids or `host_id`, each failing on its own to `null` (the tile then says "unavailable", never 0); event ids are chunked by 100 and a failed chunk nulls the figure, never a partial sum; no event ids means no query. `getHostRevenue(db, hostId, { sinceIso })` adds `completed_at >= sinceIso` to the payments read when asked; the default call is unchanged. The window starts at local midnight 30 days back on the host's anchor studio clock (`addDaysISO` + `zonedWallClockToInstant`), so the date column and the timestamp columns share one boundary across a daylight-saving change. Read-only: no API change, no migration. Known limits: the window is today minus 30 inclusive (31 calendar days), and bookings and views are counted over the 200 most recent events the Overview already loads. Not checked in a browser. |

| #2325 | CALENDAR.1 — add-to-calendar links on the confirmation email, the confirmed page and the event page | 2026-11-08. PR 4 of the host features design. `GET /api/public/events/[slug]/calendar.ics?wave=<id>` serves one published session as an RFC 5545 file: UTC instants from the studio's zone (`zonedWallClockToInstant`), the tenant host in the UID, the organisation's brand in the description (never a host anchor's internal label), 404 for a draft, a foreign or missing wave; rate-limited like the public payload; exempt-listed in `check:location-scoping`. `src/lib/event-calendar-links.js` builds the `.ics` route link and the Google link for a session (`eventCalendarLinks`, `buildEventCalendarIcs` on `src/lib/ics.js`). The confirmation and moved emails carry an "Add it to your calendar" line and operator copy gets `{{calendar_url}}` / `{{google_calendar_url}}`; the confirmed page shows both links and its "Where" is the server's safe venue text (`race.where`); the public event widget shows the links at once for a single-time event and after a time is picked otherwise (`calendar.by_wave`, fail-soft). Mig 820 adds `race_events.duration_minutes` (Duration on the host and staff forms, 60 when unset; Duplicate carries it). The client-side `event-ics.js` is retired. Mig 820 applied 8 Nov. |

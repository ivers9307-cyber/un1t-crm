| #2339 | WAVEWIN.2 — a race's wave release window is the event's own setting | 2026-11-09. A race's public signup page offers only the waves that start inside a window counted from the earliest wave with space; later waves appear as the front of the day fills (WAVEWIN.1). The window was one constant, 90 minutes, for every event: with 45-minute waves that is three start times, and an operator could not open more of the day from the first signup (Richard, for the 21 Nov charity day at Stillorgan). **Mig 825** adds `race_events.wave_window_minutes` (15 to 1440, NULL = 90; no client grant, the table is client-closed since mig 682). The staff event form's Waves section has a **Start times on offer** select (the next 90 minutes, 2, 3, 4 or 6 hours, or every start time at once) that says how many waves signup opens with; race kind only, the default and every other kind save null. `/api/public/events/[slug]` returns the column and `RaceSignupWidget` passes `resolveWaveWindowMinutes(race)` to `timePickerWaves`; an unreadable value falls back to 90. The create and update schemas, the POST insert, the staff read and `DUPLICATE_COLUMNS` carry it. Unchanged: host events and non-race kinds list every time, the window is display only (the register route accepts any wave), and an event with no setting behaves as before. Pinned by `src/lib/wave-window.test.js`, `src/lib/event-time-slots.test.js`, `src/components/RaceEventForm.wave-window.test.jsx`, `src/components/RaceSignupWidget.wave-window.test.jsx` and `tests/migration-825-wave-window.test.js`. The form was not opened in a browser signed in as staff. |

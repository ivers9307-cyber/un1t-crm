| #2337 | HOSTTHEME.1 — the host portal in light and dark, with a toggle | 2026-11-09. The host portal (`/host`) was one all-black look that hosts found hard to read (on the live Create an event form: labels 4.4:1, hints 3.0:1, "(optional)" 2.5:1). It now has a light theme and a fixed dark theme with a sun/moon toggle in the header and on the sign-in pages; until a host picks one it follows their device. No migration; look only apart from the items below. **How:** `--host-*` colour tokens on a `[data-host-theme]` wrapper (`light` / `dark` / `system`) in `src/app/globals.css`, exposed as Tailwind `host-*` classes; `system` resolves in CSS by `prefers-color-scheme` (no script, no flash); the choice is the cookie `host_theme` (per browser, one year; `src/lib/host-theme.js`), read by `src/app/host/layout.js` and written by `HostThemeToggle`. Every host screen moved from raw `white/NN`-on-black classes onto the class kit `src/components/host/host-ui.js` (headings, labels, hints, fields, buttons, chips, notices, panels, tabs, table rows). The five shared components with a `dark` prop (`EventSignupsCard`, `EventWaitlistPanel`, `PricingTiersEditor`, `RegistrationQuestionsEditor`, `DuplicateEventButton`) changed only inside the `dark ?` arm, which only the host portal passes; the staff arm is byte-identical. Public pages (`/h/…`, `/event/…`) are untouched and nothing is defined outside the wrapper. **Not only colour:** the event form is grouped into six panels with a one-line description each (ids, order, validation and the save body unchanged); sign-in and set-password fields gain a visible label; at phone width the email list rows and the pricing-tier date fields stack (the subject was squeezed to nothing, the dates were clipped); table row lines and the selected nav link / event tab are drawn so they show in both themes; the shared Move dialog on Attendees sits in a light island so its focus ring shows in dark; the email designer is told the theme when it opens (`unlayerThemeFor`, values `light` / `dark`: Unlayer documents `modern_*` / `classic_*`, the portal has always passed the older `dark`, and an ignored `light` falls back to Unlayer's light default). **Guards:** `tests/host-theme-contrast.test.js` reads the real token values and fails if a text token is under 4.5:1 on a surface it is used on, or a border / placeholder under 3:1, in either theme; `tests/host-theme-raw-colours-guard.test.js` fails on a raw palette, `white` / `black`, `un1t-*` or arbitrary colour class in a host file or in the host arm of the five shared components (known limit: `text-[color:…]`, `bg-[var(--un1t-…)]`, `bg-[theme(…)]` and colour inside an arbitrary shadow are not caught). **Checked:** the real components rendered to static HTML with the compiled stylesheet and looked at in both themes at 1280px and 375px. **Not checked:** nobody has used it signed in as a host (the toggle on a real session, the designer in light, native date / time / select controls on a phone).

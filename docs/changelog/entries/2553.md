| #2553 | MIAEVENTFACTS.1 — Mia says about an event only what its own page shows | 2026-11-23. In a live test Mia told a customer a raffle entry came with the event registration, which was made up: the tool said a raffle was open and nothing more. Every event in `list_upcoming_events`, upcoming or in `still_giving`, now carries what its public page shows: the description up to 1,500 characters (was 200) and, for a charity event, the charity, `donations_open` and, while the raffle sells online, `raffle_tickets` (the ticket prices) and `raffle_closes_label` (`givingDetails`, `raffleTicketLabels`, `readEventRaffles` in `src/lib/agent/event-giving.js`). A new rule in every prompt variant, `EVENT_FACTS_RULE`: say about an event only what the tool gives or what KNOWLEDGE says about it by name (the tool wins), and for anything else say so and send the event's link, which is not a handoff. `still_giving` also lists a charity event still to come that the upcoming list does not carry, with `when` (past, today, upcoming). A charity event with sign-up switched off is not offered to enter and `book_event` refuses it. A failed raffle read is `raffles_unreadable` and a failed events read is `events_unreadable`, never "nothing on"; the upcoming read takes published events only. No migration. Not yet tried with a real message. |

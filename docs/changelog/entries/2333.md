| #2333 | HOSTPORTAL.2 — one event, five tabs; warn before taking an event off sale | 2026-11-09. PR 2 of 3 of the host portal reorganisation (spec `docs/superpowers/specs/2026-11-09-host-portal-reorganisation-design.md` § 6.5), stacked on #2332. Every event in the host portal is now one page under a shared layout (`src/app/host/(portal)/events/[id]/layout.js`: back to Events, name and status, date · session times · venue · series, View event page, Duplicate, and a ⋯ menu holding Take off sale and Delete) with five tabs: **Overview** (`/host/events/<id>`: bookings, waitlist, page views and money tiles, a fill bar per session on the booking gate's count, and a one-line "price right now" from `src/lib/host-price-line.js`), **Attendees** (`/attendees`: the roster with Move and signup answers, Export CSV, the waitlist with Offer now), **Set up** (`/setup`: the edit form, now reachable for every status, with a jump bar and renamed section headings to match it), **Promote** (`/promote`: the public link with Copy, promo codes, series) and **Insights** (`/insights`: the Signups card and ratings). `/host/events/<id>/edit` redirects to Set up after the same host check and 404. Every tab page gates on `getCurrentHost()` and the event's `host_id` itself; the layout is not a gate. The form stays on Set up after a save and says "Saved."; `src/lib/unsaved-guard.js` and `GuardedLink` make nav links, tabs, back links, Duplicate, Take off sale and Delete ask before leaving unsaved edits (a new-tab click does not prompt), and Submit for review asks the host to save first when the form is dirty. Because the form now stays mounted it merges new session ids back from the refreshed page (a second save would otherwise delete and re-create a session added by the first), always sends `series_id` in edit mode, and shows the server's `message`, not its `error` code, when a save is refused. **Warn and confirm moved into this PR** so it is safe to ship alone: `reReviewReasons` / `editChangesFromInput` / `RE_REVIEW_REASON_LABEL` in `src/lib/host-events.js` are the one rule the PUT route, the form's standing notice and the new `OffSaleConfirmDialog` share (`computeEditTransition` is unchanged in behaviour); on a published event a save that changes the date, the standard price, a pricing tier or an existing session's start time asks "Take this event off sale?" and sends nothing until the host confirms, and the after-save line says the event is off sale until it is approved again, following the server's `reReview`. `DuplicateEventButton` (shared with the staff events list) now asks about unsaved edits before making the copy. No API behaviour change, no migration. Not checked in a browser (no host session locally): the preview needs a walk as a host across all five tabs by event status, a double save after adding a session, a price change on a published test event, and the header at 375px with Duplicate open. |

| #2058 | BOOKINGWINDOWS.1 — booking types take several availability windows per day | 2026-10-14. `event_types.availability` days are now a list of `{ start, end }` windows (e.g. Mon 07:00–10:00 + 17:00–20:00); the legacy single `{ start, end }` stays readable through `dayWindows()` (`src/lib/booking-windows.js`), the one reader, so no migration or backfill: a row converts on its next save. The slot engine runs one duration+buffer grid per window (public widget, day list, reschedule, `findBookableSlot`, Mia's consultation tools). BookingWidget, BookPanel, the booking-type list and the schedule overview test a day with `dayHasWindows` (`[]` is truthy); the overview dialog lists every window. The save routes refuse overlapping or backwards windows (`availabilityIssue` in `event-type-schema`), and the form flags them inline. No mobile change. |

W0.12 (#1966) made the automation save route refuse device_ids from another location, but class-climate-runner.js and bathroom-climate-runner.js still trusted the stored config: loadDeviceWithLocation returns THAT device's location + vendor credentials, so a foreign id (older config, direct SQL; live count 0) would switch another studio's AC and insert an ac_sessions row under the automation's location_id with the foreign device_id. One pure helper, assertDeviceAtLocation(device, locationId) in ac-devices.js (fails closed on a missing id), called in both runners' fireOn right after the load: a mismatch logs one structured logError line, records the fire as failed with reason device_not_at_location through the existing recordFire upsert (same detail shape as device_load_failed / vendor_error, so dashboards and the alert path see it like any other failed fire), and never reaches vendorTurnOn or the ac_sessions insert; the other devices in the config still fire. Runner-side guard only, no audit script. Tests: helper unit tests plus one per runner (in-location device fires, foreign device recorded failed, vendorTurnOn called once, no session row for the foreign device). |

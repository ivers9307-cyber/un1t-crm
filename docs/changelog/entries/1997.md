| #1997 | W1.L4 — customer-facing metadata, favicon and front page resolve by host | 2026-10-10. SaaS Wave 1 decision 4. The <title>/OG site name (both root and customer-facing resolvers, default-site-name.js), the favicon (default-favicon.js), the anonymous /api/public/branding branch (login + reset-password screens) and the /welcome front page each used to take ONE company_settings row estate-wide (first by location_id: Hatch for the name, Stillorgan for the favicon), so every tenant and the CRM itself read whichever gym sorted first. Now each resolves by the request host's organisation: resolveTenantOrgId(host) consults the in-code brand tier first (un1tdublin.com and host.un1tdublin.com carry UN1T Group's organizationId, MARKETING_ORG_ID-overridable) then tenant_domains, and getOrgCustomerBranding walks org_settings → that org's company_settings → location name per field; a CRM or unmapped host reads Repset and the /repset-mark.svg mark (the Stillorgan LEGACY_FAVICON_URL floor is gone). The seven customer layouts and the root layout pass the Host header; OG/title literals on /event/[slug], /embed/event, /welcome/[location](+/events), unsubscribe and preferences pages become the page's location brand or the host brand. Visible: on crm.repset.ie/crm.un1tdublin.com the anonymous title goes UN1T Hatch Street → Repset, the favicon → Repset mark, the login screen shows the Repset wordmark instead of a UN1T logo; on un1tdublin.com/host.un1tdublin.com/un1t-group.repset.ie it reads UN1T Dublin; event OG site names read the event's own studio (UN1T Stillorgan / UN1T Hatch Street / UN1T Dublin for PTC-anchored host events); /welcome loses the UN1T two-studio description until a chooser intro is set. headers() in the root layout renders every route dynamically. Regression tests pin that a second tenant's company_settings row cannot change another tenant's brand. |

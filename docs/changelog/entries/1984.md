| #1984 | WILDCERT.1 — automated *.repset.ie wildcard certificate renewal (Vercel order + Cloudflare DNS challenge) | 2026-10-10. No migration; nothing under `mobile/` or `shared/`, so **no OTA**. repset.ie's nameservers are Cloudflare, so Vercel cannot plant the `_acme-challenge` TXT a wildcard needs and the `*.repset.ie` certificate on the un1t-crm project has to be re-issued by hand every ~90 days (the first, issued 8 Oct, expires 2027-01-08). `.github/workflows/wildcard-cert.yml` ("Wildcard cert") does it: monthly cron on the 1st + `workflow_dispatch` with a boolean `force`; `permissions: contents: read`, `concurrency: wildcard-cert` (queued, never cancelled), 20-minute timeout. **Vercel issues the certificate; the job only answers its DNS challenge**, because custom-certificate upload (`vercel certs add` / `PUT /v3/certs`) is 402 Enterprise-only on this Pro team (verified the same day; an acme.sh + upload first cut was dropped on the branch). Steps: read the certificate served for `wildcard-probe.repset.ie` and stop if more than 45 days remain (`openssl x509 -checkend`; an unreadable probe counts as due); `PATCH /v3/certs {op:"startOrder", domains:["*.repset.ie"]}` (the API form of `vercel certs issue --challenge-only`, read from the 63.1.0 CLI source) and capture the one pending challenge's value, masked, refusing any challenge domain other than repset.ie; through the Cloudflare API resolve the zone, delete stale TXTs at `_acme-challenge.repset.ie`, create the new one (TTL 60, DNS-only) and poll 1.1.1.1 + 8.8.8.8 until it shows; `vercel certs issue '*.repset.ie'` (`op:"finalizeOrder"`, the exact command that worked by hand), 3 attempts 30 s apart; poll the probe up to 3 minutes until the served serial differs from the one read first AND the new notAfter is more than 60 days out. The TXT is left in DNS on purpose. No key, account or certificate file ever touches the runner. Secrets: `CLOUDFLARE_DNS_API_TOKEN` (Zone:DNS:Edit + Zone:Zone:Read on repset.ie only), `VERCEL_TOKEN` (team-scoped); no repo variable. `docs/ops/wildcard-cert-renewal.md` holds the why, the Enterprise gate, the scopes, the manual run, the manual fallback (the same two CLI commands with the TXT added by hand) and the probe host; linked from `docs/architecture/INTEGRATIONS.md`. Verified: actionlint + shellcheck clean, the two API calls against the real CLI source, the due-check and verify shells green against the live probe. **Not run end to end** (the secrets did not exist yet); the first run after they do is a forced manual one. |

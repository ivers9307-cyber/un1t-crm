| #1984 | WILDCERT.1 — automated *.repset.ie wildcard certificate renewal (Cloudflare DNS-01 → Vercel) | 2026-10-10. No migration; nothing under `mobile/` or `shared/`, so **no OTA**. repset.ie's nameservers are Cloudflare, so Vercel cannot plant the `_acme-challenge` TXT a wildcard needs and the `*.repset.ie` certificate on the un1t-crm project is a hand-renewed one (the first expires 2027-01-08). `.github/workflows/wildcard-cert.yml` ("Wildcard cert") renews it: monthly cron on the 1st + `workflow_dispatch` with a boolean `force`; `permissions: contents: read`, `concurrency: wildcard-cert` (queued, never cancelled), 20-minute timeout. It reads the certificate served for `wildcard-probe.repset.ie` and stops if more than 45 days remain (`openssl x509 -checkend`; an unreadable probe counts as due), issues with acme.sh pinned to tag 3.1.6 AND its commit and run from the shallow clone (no install), `--dns dns_cf` with `CF_Token` + a `CF_Zone_ID` looked up through the same token and masked, server letsencrypt, ec-256, account email from the repo variable `ACME_ACCOUNT_EMAIL` (required, so nothing is hard-coded in a public repo), uploads with `vercel certs add --crt cert.pem --key key.pem --ca ca.pem` (leaf + key + intermediate chain, which is what the 63.1.0 CLI PUTs to `/v3/certs` as `{cert,key,ca}`), polls the probe up to 3 minutes until the served serial is the new one, and shreds the working directory in an `always()` step. Secrets: `CLOUDFLARE_DNS_API_TOKEN` (Zone:DNS:Edit + Zone:Zone:Read on repset.ie only), `VERCEL_TOKEN` (team-scoped). `docs/ops/wildcard-cert-renewal.md` holds the why, the scopes, the manual run, the manual fallback (`vercel certs issue --challenge-only` → TXT → issue) and the probe host; linked from `docs/architecture/INTEGRATIONS.md`.

| #2331 | RATINGCOPY.1 — the host edit page loads the saved rating request copy | 2026-11-09. From HOSTPAGE.2 (#2327, 8 Nov) the host edit page selected `race_events.rating_email_subject` / `rating_email_intro` and never put them in the `initial` object it hands `HostEventForm`; the form posts every field and `PUT /api/host/events/[id]` writes each as `input.x ?? null`, so a host's customised rating request copy was wiped by their next save of that event and the Email copy section opened collapsed. The row → `initial` mapping is now `hostEventFormInitial()` (`src/lib/host-event-form-initial.js`), which carries both. Two more gaps of the same class closed: `POST /api/host/events` accepted the two fields in the schema and never inserted them, and `DUPLICATE_COLUMNS` (`src/lib/event-duplicate.js`) carried every other email copy pair but not this one. The staff event edit never writes the two columns (its body schema does not know them), so it was left alone. New guard `tests/host-event-edit-roundtrip-guard.test.js` reads the PUT route's update literal and fails when it writes a body column the mapper does not return, the edit page does not select, or the create route does not insert. Prod, read-only, 9 Nov: 16 host events, none with rating copy, none created or updated since mig 823, so nothing was lost. No migration. |

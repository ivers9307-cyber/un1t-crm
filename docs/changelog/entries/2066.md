| #2066 | TVTOAST.1 — studio TV toasts never auto-dismissed | 2026-10-15. The live board ticks `setNow(new Date())` every second for the header clock, so the parent re-renders at 1 Hz and hands `<ToastLayer>` a NEW inline `onDone` each time; the effect listed `onDone` in its deps and clears its timers on cleanup, so the `TOAST_MS=6000` dismiss timeout was torn down and restarted six times over before it could fire. **No toast on this board had EVER auto-dismissed** — the first toast of a page load stuck permanently and, since only `queue[0]` renders, every later toast (a real member's zone crossing mid-class) queued behind it unseen. Found live: `Strap 49931 just hit Zone 5 — Redline` burned on stillorgan-tv1 and tv2 for ~4h with the header reading `0 live`, ~4h after that strap's session ended at 18:10 UTC (two screenshots 4 min apart were identical while the clock ticked — that is what ruled out a transient). Cleared on the night by `pkill -f 'usr/lib/chromiu[m]'` on both kiosks. Fix holds `onDone` in a ref and depends only on `active`, so the component is correct whatever callback identity a parent passes (rather than a `useCallback` at the one call site). Test re-renders the parent every second for 10s past `TOAST_MS` and asserts exactly one dismissal (fails on main with 0); fake clock inside `act()` per the invariant. NOT included: unpaired straps can still raise a toast naming a bare device number no member recognises — a product call, not this bug. |

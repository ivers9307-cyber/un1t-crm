# App usage (USAGE.1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Record staff sessions and per-feature visits on the phone app and web CRM, and show them on a master-only platform console page.

**Architecture:** A pure client state machine (`shared/usage-tracker.js`) turns route changes and foreground/idle events into session + visit batches, which phone and web post to `POST /api/usage/events`. A 15-minute cron rebuilds per-day totals from the raw rows and enforces retention. `/admin/app-usage` (platform console) reads totals and raw rows through two master-only routes.

**Tech Stack:** Next.js 16 App Router, Supabase (service role), Expo Router, Vitest, Zod.

**Spec:** `docs/superpowers/specs/2026-10-26-app-usage-design.md`

## Global Constraints

- Staff only; masters, `impersonatingFrom` and `supportSession` are never recorded (client skips; server refuses with `{ success: true, data: { recorded: false } }`, status 200, so phone `api()` parses it).
- Only feature keys leave the device: no paths, record ids, IPs or user agents.
- Raw `app_usage_sessions` / `app_usage_visits`: 90 days. `app_usage_daily`: 400 days.
- Visit < 2 s dropped; visit capped at 4 h; flush every 60 s; web idle 5 min (session ends at last input); client keeps at most 10 unsent batches.
- Ingest clamp: times ≤ server now + 2 min, ≥ now − 48 h (whole batch dropped if session older); ≤ 200 visits a batch.
- Tables service-role only: RLS on, no policy, `REVOKE ALL … FROM anon, authenticated`.
- Report: master only (`user.profileRole === 'master'` and not impersonating), cross-tenant with optional `organization_id` / `location_id`; 404 for a person outside the chosen organisation.
- Daily day = the session's studio zone (`zoneOfLocation`), else `PLATFORM_TZ`.
- Total time = union of spans (per platform; `all` = union across both); feature time = sum of visits.
- Mobile imports `shared/...` as the `shared` package (`shared/usage-tracker`); web imports `@shared/...`.

## Review Focus

1. **A batch re-sent after a network blip** must upsert, never double count → ingest test sends the same batch twice and asserts one session and the same visit rows.
2. **Session crossing local midnight** (night shift on web) must split across two days → rollup test with a 23:50–00:20 Dublin session.
3. **Phone and web open at the same time** must not double the headline total → rollup test asserts `all` union < phone + web sum.
4. **A session id belonging to another profile** must not be overwritten → ingest test asserts the batch is dropped.
5. **A device clock hours ahead** must be clamped, not stored in the future → ingest clamp test.
